## Safety & invariants

The reranker only reorders an already scope/permission-filtered candidate set, so **scope/permission leakage stays 0 by construction** (every candidate shares the query's scope — asserted in `evaluate`). Refusal behaviour is untouched: the reranker never runs on a refused query, and never changes the decision, only the order of precedent.

## Rollback plan

The reranker ships behind a `RERANK_ENABLED` flag as an optional layer over the same candidates. **Rollback = set the flag false** — the system reverts to the RRF baseline instantly, with no data migration and no index change. The baseline is registered as `v0` (identity reranker); the reranker artifact + this report + the frozen-test manifest hash are recorded in `registry.jsonl`. Drift watch: track P@1 label agreement on a rolling sample; if it falls to or below baseline, auto-flip the flag.
